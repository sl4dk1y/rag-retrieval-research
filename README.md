# RAG Retrieval Research

Исследование методов извлечения русскоязычных документов для Retrieval-Augmented Generation (RAG).

Исторический эксперимент на полном корпусе завершён. Дополнительная проверка BGE-M3 на сокращённом корпусе также завершена; её результаты приведены отдельно ниже. В исходном эксперименте реализованы и сопоставлены:

- **BM25** — классический разреженный лексический поиск;
- **Dense Retrieval** — `intfloat/multilingual-e5-small` + FAISS;
- **Hybrid Retrieval** — weighted Reciprocal Rank Fusion (RRF);
- ablation по `nprobe` для Dense Retrieval;
- ablation по весу BM25 для Hybrid Retrieval;
- независимая финальная оценка на `test`;
- качественный error analysis;
- агрегированные итоговые таблицы и графики.

## Research question

Какой из рассматриваемых методов обеспечивает наиболее высокое качество извлечения релевантных русскоязычных документов при одинаковых условиях эксперимента?

## Research hypotheses

Исходный исторический вопрос сохраняется: обеспечивает ли weighted hybrid retrieval более высокое качество, чем отдельные retriever-ы? Завершённое исследование включает две связанные, но различающиеся гипотезы:

- **H1:** BGE-M3 обеспечивает более высокую retrieval effectiveness, чем `multilingual-e5-small`, на фиксированной reduced-1M коллекции.
- **H2:** добавление лексического BM25 через фиксированный weighted Reciprocal Rank Fusion даёт последовательное улучшение относительно соответствующего standalone dense retriever-а.

На выбранной reduced-1M коллекции наблюдаемые TEST-результаты и номинальные парные тесты поддерживают H1. H2 не поддерживается: статистически значимого улучшения не обнаружено ни для E5 + BM25, ни для BGE-M3 + BM25. Это отсутствие значимого улучшения не доказывает нулевой эффект, эквивалентность или значимое ухудшение. Выводы относятся к проверенным конфигурациям и коллекциям, а не ко всем датасетам, fusion weights или архитектурам.

## Historical full-corpus dataset and protocol

Используется русскоязычная часть **Mr. TyDi**.

- корпус: **9 597 504 документа**;
- используются `train`, `dev` и `test`;
- параметры методов выбирались только по `dev`;
- после выбора конфигурации параметры фиксировались;
- `test` использовался для финальной оценки исторического полного корпуса и не применялся для дополнительного tuning в этом эксперименте;
- финальный `test` содержит **995 запросов**.

## Experimental environment

Эксперименты выполнялись локально на Apple Silicon:

- MacBook Air;
- Apple M4;
- 16 GB unified memory;
- macOS;
- PyTorch MPS для Dense Retrieval;
- Python 3.12.

Эти характеристики следует учитывать при интерпретации приведённых измерений времени выполнения. Абсолютные latency и throughput зависят от оборудования и программного окружения.

## Methods

### BM25

Финальная конфигурация:

- `bm25s`;
- Lucene BM25;
- `k1 = 1.2`;
- `b = 0.75`;
- русский Snowball stemmer;
- документ: `title + " " + text`;
- top-100.

### Dense Retrieval

Финальная конфигурация:

- модель: `intfloat/multilingual-e5-small`;
- embedding dimension: **384**;
- документы: `passage: <title> <text>`;
- запросы: `query: <text>`;
- normalized embeddings;
- FAISS `IVFScalarQuantizer`;
- SQ8;
- inner product;
- фактический индекс: `nlist = 2048` (исторический builder имеет default `4096`);
- `nprobe = 256`;
- top-100.

Полный индекс занимает около **3.5 GB**. Peak RSS при его построении составлял около **3.74 GiB**, скорость кодирования полного корпуса — около **92.64 docs/s**.

### Hybrid Retrieval

Dense и BM25 объединяются методом weighted Reciprocal Rank Fusion:

```text
score(d) =
w_BM25 / (k + rank_BM25(d))
+
w_Dense / (k + rank_Dense(d))
```

Финальная конфигурация:

- `k = 60`;
- BM25 top-100;
- Dense top-100;
- Dense `nprobe = 256`;
- `w_Dense = 1.0`;
- `w_BM25 = 0.025`;
- Hybrid top-100.

## Historical full-corpus final TEST results

| Метод | Recall@1 | Recall@5 | Recall@10 | MRR@10 | nDCG@10 |
| --- | ---: | ---: | ---: | ---: | ---: |
| BM25 | 0.164154 | 0.296650 | 0.364824 | 0.239390 | 0.260872 |
| Dense E5, nprobe=256 | 0.434003 | **0.741039** | **0.810553** | 0.596679 | 0.639182 |
| Hybrid RRF, w_BM25=0.025 | **0.434171** | 0.736013 | 0.809548 | **0.597441** | **0.639626** |

![Final test comparison](results/final/figures/test_comparison.png)

Dense Retrieval существенно превосходит BM25. Dense и Hybrid показывают почти одинаковое качество: Hybrid немного лучше по Recall@1, MRR@10 и nDCG@10, тогда как Dense немного лучше по Recall@5 и Recall@10.

| ---: | ---: | ---: | ---: | ---: | ---: |

| 0.500 | 0.276364 | 0.570182 | 0.721455 | 0.402610 | 0.478109 |

| 0.050 | 0.377455 | 0.698909 | 0.786182 | 0.513499 | 0.579554 |

При увеличении вклада BM25 качество Hybrid заметно ухудшается. Лучшие конфигурации находятся близко к Dense Retrieval, то есть лексический сигнал оказывается полезен только при небольшом весе.

## Retrieval latency

На финальном `test`:

- BM25 retrieval: около **46.3 мс/запрос**;
- Dense FAISS search (`nprobe=256`): около **35.9 мс/запрос**;
- кодирование 995 Dense-запросов: около **2.34 с**.

![Test latency](results/final/figures/latency_test.png)

Значения отражают конкретное локальное экспериментальное окружение и не являются универсальным benchmark оборудования.

## Qualitative error analysis

Error analysis выполнен на тех же **995 test-запросах** при cutoff `@10`.

Основные категории:

- все три метода успешны: **373**;
- все три метода не находят релевантный документ в top-10: **146**;
- Dense успешен, BM25 неуспешен: **455**;
- BM25 успешен, Dense неуспешен: **20**;
- Dense успешен, Hybrid неуспешен: **1**.

При прямом сравнении Dense и Hybrid:

- Hybrid лучше Dense: **58 запросов**;
- Dense лучше Hybrid: **48 запросов**;
- результат одинаков: **889 запросов**.

![Error analysis categories](results/final/figures/error_analysis_categories.png)

Это подтверждает количественные результаты: Hybrid способен менять ранги в обе стороны, но для подавляющего большинства запросов практически повторяет Dense. Отдельно остаётся небольшой класс запросов, где лексический BM25 находит релевантный документ, пропущенный Dense, однако выбранный небольшой вес BM25 недостаточен, чтобы систематически переносить это преимущество в Hybrid top-10.

Подробный анализ: [docs/error-analysis.md](docs/error-analysis.md).

## Main findings

1. **Dense Retrieval значительно превосходит BM25** на рассматриваемой русскоязычной части Mr. TyDi.
2. `multilingual-e5-small` обеспечивает сильный retrieval baseline даже при компактной размерности embeddings.
3. Увеличение `nprobe` последовательно улучшает качество Dense Retrieval на `dev`, но увеличивает вычислительную стоимость.
4. Наивный Hybrid с равными весами существенно хуже Dense.
5. Снижение веса BM25 позволяет Hybrid приблизиться к Dense.
6. Финальный Hybrid немного улучшает Recall@1, MRR@10 и nDCG@10, но немного уступает Dense по Recall@5 и Recall@10.
7. **Устойчивого превосходства Hybrid над Dense не обнаружено.**
8. Качественный анализ подтверждает, что BM25 и Dense имеют отдельные взаимодополняющие случаи, однако простой weighted RRF не полностью реализует этот потенциал.

## Completed modern retriever validation on the reduced collection

Дополнительный эксперимент использовал **1 000 000 документов**, выбранных из исходных **9 597 504**. Пять методов — BM25, E5, E5 + BM25, BGE-M3 и BGE-M3 + BM25 — оценивались на одном фиксированном сокращённом корпусе. DEV содержит 1 375 запросов, TEST — 995. Полный протокол, конфигурации и DEV-таблица находятся в [документе эксперимента](docs/modern-retriever-validation-protocol.md); [переносимый manifest](data/reduced-1m-manifest.json) фиксирует выборку и SHA-256 корпуса.

| Reduced-corpus TEST method | Recall@1 | Recall@5 | Recall@10 | MRR@10 | nDCG@10 |
| --- | ---: | ---: | ---: | ---: | ---: |
| BM25 | 0.173199 | 0.303183 | 0.369347 | 0.247903 | 0.268482 |
| E5 | 0.437521 | 0.740536 | 0.813065 | 0.599389 | 0.641458 |
| E5 + BM25 | 0.432663 | 0.738023 | 0.812563 | 0.598179 | 0.640806 |
| BGE-M3 | 0.479899 | 0.800335 | 0.861307 | 0.651545 | 0.692026 |
| BGE-M3 + BM25 | 0.469849 | 0.797822 | 0.861307 | 0.646244 | 0.688075 |

Это **не** продолжение исторической таблицы выше: размер и состав коллекции изменились. BGE-M3 dense (`BAAI/bge-m3`, 1024 измерения, max sequence length 512) и E5 (384 измерения) использовали нормализованные embeddings и FAISS IVF SQ8, `nlist=2048`, `nprobe=256`; BM25 использовал Lucene BM25 `k1=1.2`, `b=0.75`. Для обоих гибридов был зафиксирован weighted RRF с `k=60`, dense weight 1.0 и BM25 weight 0.025. BGE-M3 был настроен и заморожен до TEST. [Сохранённые DEV/TEST runs и метрики](results/reduced-1m/) позволяют изучить результаты без повторного поиска.

Три заранее заданных парных сравнения на TEST: BGE-M3 vs E5, E5 + BM25 vs E5 и BGE-M3 + BM25 vs BGE-M3. [Статистика](results/reduced-1m/tables/paired_test_statistics.json) использует 10 000 парных bootstrap-выборок, 95% percentile CI, 10 000 парных sign-flip randomizations, seed 42 и двусторонние p-values. Все **15 p-values номинальные и не скорректированы за множественные сравнения**. BGE-M3 превзошёл E5 по всем пяти TEST-метрикам; парные результаты поддерживают это преимущество на номинальном уровне значимости. Для обоих dense retriever-ов не обнаружено статистически значимого улучшения от фиксированного weighted RRF. Это не доказывает эквивалентность методов и не свидетельствует о статистически значимом ухудшении.

Фактические затраты на построение BGE-M3: **80 853.38 с** кодирования основного корпуса (около **22 ч 28 мин**), отдельно **9 932.68 с** кодирования обучающей выборки (около **2 ч 46 мин**) и **91 196.10 с** общей продолжительности построения индекса (около **25 ч 20 мин**). Это разные измерения: полное время сборки не является временем кодирования документов. [Исходная timing metadata](results/reduced-1m/tables/dense_bge_m3_build_timing.json) сохраняет точные значения, измеренные локально на Apple M4/MPS.

**Ограничение интерпретации:** сокращённый корпус построен с использованием положительных DEV и TEST qrels, исторических BM25 DEV/TEST top-100 результатов, исторических E5 DEV/TEST top-100 результатов и seeded random sampling (seed 42). Поэтому reduced TEST не полностью независим от построения коллекции. Она не является репрезентативной случайной выборкой исходных 9 597 504 документов; выводы условны для этой фиксированной коллекции и не устанавливают качество BGE-M3 на полном корпусе. Подробности и проверка SHA-256 приведены в [протоколе](docs/modern-retriever-validation-protocol.md).
