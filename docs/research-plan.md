# План исследования

## Рабочее название статьи

Сравнительный анализ методов извлечения русскоязычных документов для систем Retrieval-Augmented Generation.

## Цель

Экспериментально сравнить качество и производительность разреженного, плотного и гибридного поиска документов на русскоязычной части набора данных Mr. TyDi.

## Объект исследования

Компонент извлечения документов в системах Retrieval-Augmented Generation.

## Предмет исследования

Методы ранжирования русскоязычных документов по релевантности пользовательскому запросу.

## Исследовательский вопрос

Какой из рассматриваемых методов обеспечивает наиболее высокое качество извлечения релевантных русскоязычных документов при одинаковых условиях эксперимента?

## Гипотеза

Гибридный поиск, объединяющий BM25 и Dense Retrieval, способен показать более высокое качество, чем каждый метод по отдельности, поскольку BM25 использует лексические совпадения, а Dense Retrieval — семантическую близость.

## Набор данных

Русскоязычная часть Mr. TyDi:

- корпус: **9 597 504 документа**;
- train-запросы и qrels;
- dev-запросы и qrels;
- test-запросы и qrels.

Настройка параметров выполняется на `dev`. `test` сохраняется для финальной независимой оценки после фиксации конфигураций.

## Сравниваемые методы

1. **BM25** — разреженный лексический поиск.
2. **Dense Retrieval** — семантический поиск на `intfloat/multilingual-e5-small`.
3. **Hybrid Retrieval** — объединение BM25 и Dense Retrieval методом Reciprocal Rank Fusion.

## Основные метрики

- Recall@1;
- Recall@5;
- Recall@10;
- MRR@10;
- nDCG@10;
- среднее время поиска одного запроса.

## Экспериментальная конфигурация

### BM25

- `bm25s`;
- Lucene BM25;
- `k1 = 1.2`;
- `b = 0.75`;
- русский Snowball stemmer;
- документ: `title + " " + text`.

### Dense Retrieval

- модель: `intfloat/multilingual-e5-small`;
- embedding dimension: 384;
- запрос: `query: <text>`;
- документ: `passage: <title> <text>`;
- FAISS IVFScalarQuantizer + SQ8;
- inner product;
- `nlist = 2048`;
- train docs: 100 000;
- основной рабочий параметр: `nprobe = 256`;
- `nprobe = 512` — контрольная конфигурация максимального качества.

### Hybrid Retrieval

Начальная конфигурация:

- BM25 top-100;
- Dense top-100;
- Dense run: `nprobe = 256`;
- RRF constant: `k = 60`;
- итоговый Hybrid top-100.

## Ограничения

Исследование оценивает retrieval-компонент RAG-системы. Генерация ответа языковой моделью в основной эксперимент не входит.

Latency зависит от реализации, оборудования, кэша и фоновой нагрузки, поэтому интерпретируется как инженерное измерение текущего окружения.

Параметры настраиваются на `dev`. `test` не используется для подбора параметров.
